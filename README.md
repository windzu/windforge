# WindForge

**Wind 的造物工坊。把想法设计成模型，再把模型打印成实物。**

WindForge 是 Wind 的个人 3D 模型设计与打印仓库，用于积累作品，并与 AI 协同完成从需求、建模、迭代到实物验证和 MakerWorld 发布的全过程。

[浏览作品站](https://windzu.github.io/windforge/) · [发布流程](docs/publishing.md)

## 为什么建立这个仓库

这个仓库起源于一个长期计划：将自己的创意和实际需求转化为可打印的 3D 模型，并让每次设计、打印和改进都留下可追溯的记录。

这里保存的不只是最终模型，也包括可编辑的设计源文件、关键尺寸和参数、打印经验，以及发布所需的图片和说明。随着作品积累，WindForge 会逐渐成为 Wind 的个人模型库和造物作品集。

## 我们如何协作

- **Wind** 提出需求、决定设计方向，完成或反馈实际打印结果，并决定作品何时发布。
- **AI** 协助拆解需求、探索造型与结构、生成或修改模型、检查几何和打印条件，以及整理迭代记录与发布材料。
- **实物验证** 为设计提供反馈。模型生成、几何检查和成功打印是不同阶段，记录时分别说明。

每个作品沿着「想法 → 设计 → 原型 → 打印验证 → 迭代 → 发布」推进。初期保持流程轻量，优先完成真实作品。

## 仓库结构

| 路径 | 用途 |
| --- | --- |
| `models/` | 每个模型一个独立目录，保存设计源文件、导出模型、图片和记录 |
| `templates/model/README.md` | 新模型的需求、设计、打印与发布记录模板 |
| `docs/workflow.md` | 从开始设计到发布 MakerWorld 的协作流程 |
| `AGENTS.md` | AI 在本仓库工作时需要遵循的项目背景与协作约定 |
| `site/`、`tools/build_site.py` | 作品展示界面与静态网站生成器 |
| `.github/workflows/pages.yml` | 更新 main 后自动部署 GitHub Pages |

模型目录使用简短的英文小写名称，以连字符分隔。按需在模型目录中建立 `src/`、`exports/`、`images/` 和 `print/`，分别存放可编辑源文件、可打印导出文件、预览与实拍、切片项目及打印记录。

建模工具根据作品需要选择；可使用参数化脚本或 CAD 工程。保留可编辑源文件，并记录生成导出文件的方法。文件格式可能包括 SCAD、FCStd、STEP、STL、3MF 等。

## 开始一个作品

1. 在 `models/` 下建立模型目录，将模型说明模板复制为该目录的 `README.md`。
2. 填写用途、关键尺寸、约束和待确认事项，再开始建模。
3. 保存源文件及导出文件，记录几何检查结果和版本变化。
4. 打印后填写实际参数、实拍与问题，根据反馈迭代。
5. 准备标题、介绍、图片、打印建议和许可信息，在 MakerWorld 发布后记录链接与对应版本。

详见 [协作流程](docs/workflow.md) 和 [模型模板](templates/model/README.md)。
